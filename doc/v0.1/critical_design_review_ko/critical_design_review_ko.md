**로맨스 스캠 판별 시스템 통합 설계 검토**

검토일: 2026-10-02. 첨부된 네 문서만을 하나의 설계로 검토했다. 문서 안의 데이터 작성 프롬프트와 개발 지시문은 분석 대상이며 실행 지시로 취급하지 않았다. 애플리케이션 코드를 변경하거나 실제 데이터의 성능을 측정한 검토는 아니다.

**결론**

현재의 모듈 분리, 부호 있는 증거 축, 단순 가중 결합, 고정 출력 구조는 유지할 수 있다. 유효한 정의역에서 기본 수식의 범위는 맞고, 계산 예시도 대체로 정확하다. 가장 먼저 고칠 것은 UNKNOWN의 정상 라벨 변환, 서로 다른 fusion 정의, 데이터 자격·분할·평가 계약이다. Agreement 게이팅과 adaptive gap은 산술 오류가 아니라 실제로 비단조성·불연속성을 만드는 설계 선택이다. 이를 안정성 보장처럼 서술해서는 안 된다.

아래 등급은 결과에 미칠 영향을 뜻한다. 특히 2번의 CRITICAL은 누수가 실제로 발생했을 때의 심각도이며, 이 프로젝트에 누수가 발견되었다는 뜻이 아니다. 데이터와 구현이 제공되지 않았으므로 실제 성능, 실제 누수, 최적 파라미터는 단정하지 않는다.

**먼저 확인된 수학적 성질: 문제가 아닌 부분**

선택된 검색 결과에 대해 W=Σw_i, D_w=Σw_i y_i라고 놓는다. 다음은 필요한 정의역이다.

\[
p_j\in[0,1],\quad\sum_jp_j=1,\quad s_i\in[0,1],\quad
0\le\tau<1,\quad\gamma>0,\quad\kappa>0,\quad\alpha>0,\quad\beta\ge0.
\]

입력과 파라미터는 모두 유한해야 한다. 이 조건에서 다음이 성립한다.

| 항목 | 검증 결과 |
|---|---|
| M=p_S-p_N | -1≤M≤1이고 더 강하게 \(|M|\le1-p_U\)이다. UNKNOWN 점수가 증가하면 가능한 증거 크기의 상한은 줄어든다. |
| w_i | threshold를 통과한 결과에서 0≤w_i≤1. γ>0이면 similarity에 대해 단조 증가한다. |
| R=D_w/W | W>0이면 비음수 가중 평균이므로 -1≤R≤1. |
| Q=1-exp(-W/κ) | 실수 연산에서 0≤Q<1. W에 대해 단조 증가한다. |
| A=\|R\|, Q_eff=QA | 0≤A≤1, 0≤Q_eff<1. |
| E=(αM+βqR)/(α+βq) | q=Q 또는 Q_eff일 때 모두 M과 R의 볼록결합이므로 -1≤E≤1. |
| S=50(1+E) | 0≤S≤100. E에 대해 엄격히 증가한다. |

K_max=5, κ=1인 기본값에서는 W≤5이므로 Q≤1-e^-5≈0.993262이다. 실수상 Q<1이지만 부동소수점에서는 작은 κ 등으로 Q가 정확히 1로 반올림될 수 있다. 그 자체로 범위 이탈이나 위험한 overflow는 아니다.

W=0 처리는 S §20.1과 R 의사코드에 이미 있다. 모든 검색 결과가 s=τ이면 후보 개수가 양수여도 W=0이며 이 분기가 적용된다. 따라서 “0분모 처리가 전혀 없다”는 지적은 틀리다. 기본 α=1에서는 fusion의 분모도 1 이상이다.

Q와 A는 서로 다른 요약을 제공한다. Q는 가중치 총량 W를, A는 가중 라벨의 불균형 |D_w|/W를 측정한다. 예를 들어 같은 W에서 라벨 구성을 바꾸면 Q는 같고 A는 달라진다. 둘이 통계적으로 독립이라는 보장은 없지만, 같은 정보라고 단정할 수도 없다. 반면 A는 R의 결정적 함수이므로 R에 비해 새로운 정보는 없다.

S §14의 예시 M=.54, R=.5, W=2.2는 Q≈.889197, S≈76.0587로 계산되어 문서의 76.1과 일치한다. R의 검색 결과 4개 예시는 gap 필터를 통과한 집합으로 해석하거나 δ=.15를 사용하면 맞다. δ=.10이면 마지막 결과가 제외되어 다른 수치가 나온다.

**1. CRITICAL — UNKNOWN과 미지원 라벨을 NON_SCAM 증거로 변환한다**

1. **위치:** D §3.3·3.4, R §7 및 의사코드 891행.
2. **발생 조건:** UNKNOWN, 오타, 빈 라벨 등 SCAM 이외의 값이 검색 결과에 들어온다.
3. **왜 문제인가:** `+1 if label == "SCAM" else -1`은 UNKNOWN을 판단 보류가 아닌 정상 증거로 만든다. D의 3클래스 계약과 R의 이진 라벨 계약이 연결되지 않았다. 별도로 verified=false인 이진 라벨도 현재는 확정 증거와 같은 방식으로 사용될 수 있다.
4. **반례:** similarity=1, label=UNKNOWN 한 건, M=0이면 R=-1, Q=.632121, S=30.63499로 LOW/NON_SCAM이 된다.
5. **수정 여부:** 필수.
6. **최소 수정:** RAG index 입고 조건을 `verified==true` 및 `label in {SCAM, NON_SCAM}`으로 명시한다. 계산에서도 두 라벨만 명시적으로 매핑한다. UNKNOWN은 방향 증거에서 제외하고, 미지원 라벨은 데이터 오류로 처리한다. 자격 필터는 가능하면 후보 검색 전에 적용하여 무효 데이터가 Top-8을 차지하지 않게 한다.
7. **부작용:** 사용 가능한 검색 결과와 coverage가 감소한다. 검증된 데이터가 적다는 사실을 숨기지 않게 되는 효과이며, UNKNOWN을 y=0으로만 바꾸면 여전히 Q를 올리는 문제가 남으므로 단순 치환은 권하지 않는다.

**2. CRITICAL·조건부 — 사건 누수가 발생하면 일반화 평가가 무효화된다**

1. **위치:** D §3.2·9.3, P §29, R §22.3·22.4.
2. **발생 조건:** 같은 사건의 원본·부분 대화·번역·의역이 Train/RAG와 Validation/Test에 나뉘거나, 평가 query가 같은 사건을 RAG에서 검색한다.
3. **왜 문제인가:** 새로운 사건에 대한 일반화 대신 이미 본 사건의 재식별을 측정한다. 문서는 누수를 이미 금지하지만 case grouping을 “가능하면”으로 표현하고 분할 manifest, Validation 격리, 파생본 계승 규칙을 확정하지 않았다.
4. **반례:** 같은 사건 전반부는 RAG, 후반부는 Test에 넣으면 conversation_id가 달라도 사건 누수다. Validation query의 자기 사건 검색도 파라미터 선택을 낙관적으로 만든다.
5. **수정 여부:** 학습·평가용 데이터 확정 전에 필수. 현재 누수가 존재한다고 확인한 것은 아니다.
6. **최소 수정:** 알려진 사건·가해자·파생 관계를 그룹화한 뒤 split manifest를 먼저 고정한다. 증강·분할·번역은 원본 split을 상속한다. Validation과 Test의 그룹은 모델 학습 및 해당 평가에서 사용하는 RAG corpus와 겹치지 않게 한다. 검증 과정에서 미확인 그룹을 자동으로 독립 사건이라고 간주하지 않는다.
7. **부작용:** 독립 평가 사건 수가 줄고 클래스 균형이 달라질 수 있다. Train과 RAG가 서로 겹치는 것은 그 자체로 평가 누수가 아니며, 둘의 완전 분리를 무조건 강제할 필요는 없다.

**3. HIGH — 최종 fusion 함수가 두 가지이며 모듈 계약이 결정되지 않았다**

1. **위치:** S §8·18·23 대 R §14·15·24, P §11·23·26.
2. **발생 조건:** S의 Q를 그대로 쓰는 구현과 R의 Q_eff를 쓰는 구현이 각각 문서를 따른다.
3. **왜 문제인가:** S는 \(E_Q=(M+QR)/(1+Q)\), R은 \(E_A=(M+Q|R|R)/(1+Q|R|)\)를 권장한다. P는 두 값을 구별하지 않고 rag_quality 하나만 전달한다. 같은 데이터로 서로 다른 시스템이 만들어진다.
4. **반례:** M=.35, R=0, W=2이면 Q=.864665이다. E_Q 방식은 59.385로 UNKNOWN, E_A 방식은 67.5로 HIGH다. 충분하지만 균형 잡힌 검색 결과를 “모델 판단을 완화하는 증거”로 볼지 “방향성이 없어 무시할 증거”로 볼지 다르다.
5. **수정 여부:** 필수. 두 수식 중 어느 것이 일반적으로 우수한지는 실험 문제다.
6. **최소 수정:** 원래 Risk 문서를 기준선으로 Q fusion을 기본값으로 두고 Q_eff fusion은 명시적 실험 옵션으로 분리하는 것이 변경량이 작다. 또는 반대로 선택해도 되지만 단일 기준 문서와 `fusion_mode`를 정하고 raw Q와 Q_eff를 별도 필드로 전달해야 한다. Agreement를 두 번 적용하지 않도록 한다.
7. **부작용:** 선택한 모드에 따라 기존 threshold와 UNKNOWN 비율이 달라져 재검증이 필요하다.

**4. HIGH — 라벨의 대상과 verified의 의미가 충분히 구별되지 않았다**

1. **위치:** D §2 기본 예시, §3.3·3.4, §4.1~4.4.
2. **발생 조건:** 확인된 사건 결과, 대화만 보고 한 사람의 판단, 현재 발화에서 관찰한 신호를 같은 정답으로 섞는다.
3. **왜 문제인가:** 사건이 실제 사기였는지와 지금 입력에 사기 신호가 관찰되는지는 다른 목표다. UNKNOWN은 제3의 사건 유형이라기보다 주석 정보의 불충분함일 수 있다. verified=true도 “사람 확인”과 “사건 자료 확인”을 구별하지 않는다.
4. **반례:** 기본 예시는 인사와 메신저 이동뿐인데 MONEY_REQUEST와 RAPID_INTIMACY를 붙였다. 외부 사건 결과로 SCAM일 수는 있어도 입력에서 금전 요구를 관찰한 예시는 아니다. NON_SCAM 예시의 “기만 정황이 확인되지 않음”만으로 정상 사건이 확인되었다고 결론낼 수도 없다.
5. **수정 여부:** 라벨 기준 확정과 예시 보정은 필수.
6. **최소 수정:** label이 사건 결과인지 관찰 대화의 판단인지 명시하고 검증 출처·기준을 기록한다. risk_factors와 evidence는 입력에서 실제 관찰되는 항목으로 제한한다. UNKNOWN의 주석 기준과 사람이 확인하는 절차를 정한다. 사건 결과가 확인된 초기 대화는 보존할 수 있지만 초기 탐지 평가를 별도로 보고한다.
7. **부작용:** 재주석 비용과 UNKNOWN 비율이 증가할 수 있다. 라벨이 확인된 초기 대화를 무조건 버리면 초기 탐지 능력을 평가할 수 없으므로 일괄 제거는 적절하지 않다.

**5. HIGH — Agreement를 곱하는 방식에는 증거 크기의 이중 감쇠와 비단조성이 있다**

1. **위치:** R §13~15.
2. **발생 조건:** Q_eff=Q|R|를 fusion 가중치로 사용한다.
3. **왜 문제인가:** R에는 이미 라벨 상쇄가 반영되어 있다. Q_eff R=QR|R|이므로 같은 라벨 불균형을 다시 감쇠한다. 이것은 독립 정보를 추가한 것이 아니라 의도적인 게이팅이다. “보수적”이라는 표현도 UNKNOWN 쪽이 아니라 모델을 더 유지한다는 뜻이 될 수 있다.
4. **반례:** M=.8, Q=.864665를 고정하면 R=0일 때 S=90, R=.1일 때 S=87.2145이다. SCAM 방향 R이 증가했는데 점수는 감소한다. R>0에서 \(\partial E_A/\partial R=Q(2R+QR^2-M)/(1+QR)^2\)이므로 작은 양수 R에서는 실제로 음수가 될 수 있다. Q를 고정한 원래 Q fusion은 \(\partial E_Q/\partial R=Q/(1+Q)\ge0\)이다.
5. **수정 여부:** 효과와 주장의 수정은 필수. 수식 제거는 실험 결과와 의도에 따라 결정한다.
6. **최소 수정:** A는 우선 진단값으로 기록하고 Q fusion과 Q_eff fusion을 비교한다. Q_eff를 유지하면 비단조성을 명시하고 이를 “추가 신뢰 정보”가 아니라 “라벨 불일치 때 검색 가중치를 낮추는 정책”으로 설명한다.
7. **부작용:** Q fusion으로 바꾸면 R≈0인 검색 결과도 모델 점수를 50 쪽으로 낮춘다. 이것이 바람직한지는 별도의 설계 선택이다.

**6. HIGH — 강한 충돌의 완화와 UNKNOWN 출력 보장을 혼동하면 안 된다**

1. **위치:** S §1·10·22, R §15.
2. **발생 조건:** 반대 방향의 M과 R에 서로 다른 실효 가중치가 적용되거나 α·β를 변경한다.
3. **왜 문제인가:** 가중 평균은 항상 0으로 상쇄되지 않는다. M=m>0, R=-r일 때 λ=βq/α로 두면 \(E=(m-\lambda r)/(1+\lambda)\)이다. 정확한 상쇄는 m=λr일 때만 일어나고, UNKNOWN 여부는 별도 threshold까지 만족해야 한다.
4. **반례:** s=[.98,.88,.78,.70], label=[N,N,N,S], 기본 τ=.6,δ=.12,γ=κ=1이면 R=-.787234,Q=.904631이다. M=.95에서 Q fusion은 56.2438, Q_eff fusion은 61.3706으로 HIGH다. 두 결과 모두 출발 점수 97.5에서 50 방향으로 이동했으므로 이 예는 “방향 이동”의 반례가 아니라 “UNKNOWN 출력 보장”의 반례다. 일반 가중치에서는 M=.8,R=-1,Q=.9,α=1,β=20이면 E=-.905263,S=4.7368로 오히려 50에서 더 멀어질 수도 있다.
5. **수정 여부:** 보장 범위의 문서 수정은 필수. 별도 충돌 판정 규칙은 정말 UNKNOWN을 강제하려는 경우에만 필요하다.
6. **최소 수정:** “반대 증거를 반영해 완화하지만 UNKNOWN을 보장하지 않는다”로 명시한다. 일반 α·β 튜닝에서는 충돌 사례를 필수 검증한다. 강충돌 시 무조건 보류가 제품 요구라면 판정 모듈에 명시적 conflict 규칙을 추가하고 override 사유를 기록한다.
7. **부작용:** conflict 규칙은 threshold를 추가하고 한쪽이 정확한 사례도 보류할 수 있다. 현재 수식을 유지하는 경우 추가 규칙은 필수가 아니다.

엄밀히 말해 기본 α=β=1에서는 q≤1이고, 반대 R에 대해 |M|≥1/3이면 |E|≤|M|가 성립한다. 따라서 “강한 모델 증거가 반대 증거에 의해 완화된다”는 기본 설계의 방향 자체를 모두 틀렸다고 평가해서는 안 된다. 1/3은 위 성질의 충분조건이며 문서가 정의한 ‘강함’의 threshold는 아니다.

**7. HIGH — adaptive gap이 작은 similarity 변화에 큰 판정 점프를 만든다**

1. **위치:** R §5·6·18·21.
2. **발생 조건:** 인접 similarity 차이가 δ 근처에 있고 그 뒤의 라벨 구성과 앞부분이 다르다.
3. **왜 문제인가:** 첫 gap에서 뒤의 모든 결과를 제거하는 불연속 선택이다. ANN 검색의 후보 변화, embedding 갱신, 입력 표현 변화가 증폭된다. threshold와 gap의 조합 자체는 논리적으로 잘 정의되지만 안정적이라는 보장은 없다.
4. **반례:** M=-.2,δ=.12, label=[S,N,N,N,N]. s=[.94,.8199,.8199,.8199,.8199]이면 k=1,S=61.8463이다. 뒤의 네 값을 .8201로 0.0002만 높이면 k=5,S=36.3981이다(Q_eff fusion). HIGH가 LOW로 바뀐다.
5. **수정 여부:** 민감도 평가와 주장 수정은 필수. gap 자체의 제거 여부는 실험으로 결정한다.
6. **최소 수정:** fixed k+threshold+현재 weight를 기준선으로 두고 gap 유무를 비교한다. 불안정하면 gap 옵션만 끈다. tie 정렬, 첫 gap, gap 없음, 0·1개 후보, 경계 비교 규칙을 명시한다. float 허용오차는 정확한 동률 재현에는 도움이 되지만 본질적 점프를 제거하지는 않는다.
7. **부작용:** gap을 끄면 덜 관련된 이웃도 포함될 수 있다. 기존 가중치가 이미 그 영향을 낮추므로 추가 복잡한 필터를 먼저 도입할 필요는 없다.

threshold만 놓고 보면 γ>0에서 s가 τ를 넘어올 때 w→0이다. 따라서 threshold가 있다는 이유만으로 최종 점수에 항상 큰 점프가 생긴다고 주장하는 것도 부정확하다. 여기서 큰 점프의 원인은 여러 이웃을 한 번에 제거하는 선택 규칙이다.

**8. HIGH — 중복·단일 검색 결과에 대한 Quality 해석이 과도할 수 있다**

1. **위치:** R §10·12·13·19·22.3·22.4, S §6·7, D §3.2.
2. **발생 조건:** 같은 사건의 여러 대화·복사본이 선택되거나 gap으로 한 건만 남는다.
3. **왜 문제인가:** Q는 총 가중치의 포화 함수이지 독립 표본 수나 정답 신뢰도의 추정량이 아니다. 중복은 방향과 Q를 동시에 강화한다. 한 건만 있어도 A=1이므로 Agreement=1은 여러 독립 사건의 합의를 뜻하지 않는다. R=1도 모든 가중치가 매우 작을 때 가능하다.
4. **반례:** M=-.3이고 s=.9인 SCAM 한 건이면 S=57.4505다. 같은 자료를 5번 넣으면 R은 그대로인데 Q가 .527633에서 .976482로 증가하여 S=67.1133이 된다. M=0일 때 s=1인 잘못된 이웃 한 건만으로도 S=69.365가 된다. 다만 기본 설정에서 한 건의 실효 비중은 최대 .6321/1.6321≈38.73%이므로 “한 건이 항상 전부 결정한다”는 주장도 과장이다.
5. **수정 여부:** 중복 통제와 해석 수정은 필수. 단일 이웃의 허용 정도는 실험 문제다.
6. **최소 수정:** 정확 중복·파생본을 index 단계에서 제거하고, 현재 선택 집합에서 같은 case_group_id는 한 건만 남기는 규칙을 기준선으로 둔다. 검색 후 중복 제거 때문에 유효 후보가 부족해지는 경우 추가 조회 정책을 정한다. Q는 ‘검색 가중치 총량 지수’, A는 ‘가중 라벨 일치도’로 설명한다.
7. **부작용:** 사건당 한 건 제한은 서로 다른 단계의 유용한 대화를 줄일 수 있고 조회 비용을 늘릴 수 있다. 실제 다양성이 있는 사건 내 대화를 살릴지는 후속 실험으로 정한다.

**9. HIGH — RAG 클래스 비율과 평가 클래스 비율이 서로 다른 경로로 편향을 만든다**

1. **위치:** D §8, R §22.2, P §13, S §16.
2. **발생 조건:** embedding이 라벨을 잘 구분하지 못하고 한 클래스가 RAG DB를 지배하거나, 5:5 학습 비율을 운영 성능 해석에 그대로 사용한다.
3. **왜 문제인가:** R은 가까운 사례의 가중 라벨 비율이므로 corpus의 국소 구성 영향을 받는다. 5:5 학습은 틀리지 않지만 Precision·Accuracy·F1과 비용 총합은 평가 분포의 영향을 받는다. TPR/FPR도 집단 구성 변화가 있으면 자동으로 불변하지 않는다.
4. **반례:** 유사도에 라벨 구별력이 없고 같은 가중치로 이웃이 선택되는 조건에서 DB 비율이 9:1이면 검색 R의 기대값은 .8로 SCAM 쪽이다. 별도로 TPR=.9,FPR=.1이 같다고 가정하면 SCAM 비율 50%에서 Precision=.9, 1%에서는 .08333이다. 정상 99%에서 모두 정상으로 출력하면 Accuracy=99%, SCAM Recall=0이다.
5. **수정 여부:** 평가 분포의 구분은 필수. class-balanced retrieval이나 prior correction은 실험 후 결정한다.
6. **최소 수정:** Train/RAG/Validation/Test의 클래스 비율과 독립 사건 수를 각각 기록한다. 클래스별 confusion, macro 지표, SCAM PR 지표, 대표 분포와 hard-negative 성능을 보고한다. RAG 비율을 바꿔 sensitivity를 측정하고 비용 최적화에는 목표 분포를 반영한다.
7. **부작용:** 강제 균형 검색은 실제로 관련 있는 다수 클래스 이웃을 버리거나 관련 없는 이웃을 채울 수 있다. 라벨 비율 보정을 무조건 적용하는 것도 새로운 편향이다.

**10. HIGH — 의미 유사성과 라벨 일관성은 현재 사례의 정답 근거를 보장하지 않는다**

1. **위치:** P §6·30, R §10~15, S §10·22의 ‘독립적인 근거’ 표현.
2. **발생 조건:** 정상 송금·정상 투자·연애와 스캠이 비슷한 표현을 쓰거나 Model과 RAG가 같은 잘못된 단서에 반응한다.
3. **왜 문제인가:** label과 similarity만의 가중투표는 단순한 baseline으로 타당하지만, 검색 유사도를 논리적 함의나 calibrated reliability로 해석할 수는 없다. 별도 모듈이라는 사실도 오류의 통계적 독립성을 보장하지 않는다. 다만 이 가중 평균 수식이 확률적 독립성을 전제로 해야만 성립하는 것은 아니다.
4. **반례:** “급히 돈을 보내 달라”는 정상 가족 대화가 스캠 이웃과 높은 similarity를 보일 수 있다. 모델도 같은 표현에 오판하면 M=.8,R=1,Q≈1이 합쳐져 S≈95로 공동 오류를 강화한다.
5. **수정 여부:** 근거 수준과 독립성 주장 수정은 필수. 더 복잡한 모델 도입은 필수가 아니다.
6. **최소 수정:** ‘분리된 두 모듈’과 ‘통계적으로 독립적인 근거’를 구별한다. D §7의 어려운 정상 사례를 실제 평가에 포함하고 이웃 라벨 정합성, Model/RAG 오답 교집합, 불일치 사례에서 fusion의 순개선을 측정한다.
7. **부작용:** 어렵지만 현실적인 평가에서는 성능이 낮아질 수 있다. 이는 설계를 복잡하게 해야 한다는 근거가 아니라 현재 적용 범위를 드러내는 결과다.

**11. HIGH — 정규화, 모델 정확도, calibration을 구별해야 한다**

1. **위치:** S §3.1·20.3, P §4·19·31.
2. **발생 조건:** raw logits나 일부 label token의 log probability를 p로 직접 사용하거나, 합이 1인 점수의 크기를 검증된 신뢰도로 해석한다.
3. **왜 문제인가:** logits에는 [0,1] 제약이 없고 log probability는 음수다. softmax는 값의 범위를 맞추지만 calibration을 보장하지 않는다. 세 라벨만 재정규화하면 원래 모델이 그 라벨 집합에 거의 질량을 주지 않았다는 사실이 사라질 수도 있다. 여러 토큰으로 된 라벨은 첫 토큰 확률만 비교하면 같은 분류 문제가 아니다.
4. **반례:** 2클래스 예에서 logits=(2,0)의 softmax는 약 (.8808,.1192), temperature=10이면 (.5498,.4502)다. argmax와 그에 따른 Accuracy는 같지만 margin은 .7616에서 .0997로 변한다. 같은 정분류율이 같은 evidence 크기를 의미하지 않는다.
5. **수정 여부:** 출력 변환 계약은 필수. calibration 절차 도입은 실제 점수 품질에 따라 판단한다.
6. **최소 수정:** 허용 출력 형태를 하나로 정하고 logits→안정적 softmax, log-probability→log-sum-exp 기반 정규화 등 변환을 명시한다. p는 finite·비음수·합1 검사 후 사용한다. 생성된 ‘87%’를 사용하지 않는 기존 원칙을 유지하고 validation에서 confidence와 오류율 관계 및 score scaling 민감도를 확인한다.
7. **부작용:** score scaling을 보정하면 M 크기와 최종 threshold가 함께 바뀌므로 다시 고정해야 한다. 작은 데이터에 calibration까지 과도하게 맞추면 과적합될 수 있다.

네 문서에는 “Accuracy가 특정 수치 이상이므로 개별 샘플이 신뢰할 만하다”는 명시적 가정이 없다. 따라서 그런 오류를 저자가 이미 범했다고 단정하지 않는다. 높은 Accuracy와 calibration이 별개라는 근거는 [Guo et al., ICML 2017](https://proceedings.mlr.press/v70/guo17a.html)에서 확인할 수 있다.

**12. HIGH — Model UNKNOWN이 최종 보류와 같은 의미인지 미정이다**

1. **위치:** S §3.2·15·17, D §3.3, P §13.
2. **발생 조건:** UNKNOWN이 모델 argmax이면 최종 UNKNOWN이어야 한다고 기대하거나, M=0을 모델 증거 부재와 동일하게 해석한다.
3. **왜 문제인가:** M=p_S-p_N은 방향 요약으로는 타당하지만 원래 3차원 출력의 불확실성 원인을 보존하지 않는다. p_U는 |M|의 상한에 반영될 뿐 별도 보류 규칙이 아니다. α는 M=0일 때도 분모에 남는다.
4. **반례:** (p_S,p_N,p_U)=(.48,.03,.49)이면 모델의 최대 클래스는 UNKNOWN이지만 M=.45이고 RAG 없이 S=72.5다. (.5,.5,0)과 (0,0,1)은 모두 M=0이다. M=0,α=β=1이면 가장 강한 RAG에서도 -0.5<E<0.5여서 25<S<75이다. T_H≥75이면 RAG만으로 HIGH를 만들 수 없다.
5. **수정 여부:** 의미 확정은 필수. 이 변환을 수학 오류로 폐기할 필요는 없다.
6. **최소 수정:** M을 ‘3클래스 argmax 판정’이 아닌 ‘방향 margin’으로 명시하고 p_U를 로그에 보존한다. UNKNOWN argmax 보류가 필수 요구라면 판정 모듈에서 별도로 정하되, RAG가 이를 해소할 수 있는지도 함께 명시한다. 높은 p_U를 처리하려고 α를 자동 변경하는 새 수식은 먼저 도입하지 않는다.
7. **부작용:** 모델 UNKNOWN을 강제 보류하면 RAG가 올바르게 해소하는 사례도 막을 수 있다. 기존 압축을 유지하면 상태 구별은 로그와 출력 이유가 담당해야 한다.

**13. HIGH — 수식의 정의역이 구현 설정 검증으로 완성되어 있지 않다**

1. **위치:** R §8·9·12·21, S §8·19·20.
2. **발생 조건:** τ=1, γ≤0, κ≤0, α=0, 음수 β, NaN/Inf 점수, 역전된 threshold 등이 설정되거나 외부 입력으로 전달된다.
3. **왜 문제인가:** 기본값은 안전하지만 일반 파라미터의 범위가 명시적 계약이 아니다. 특히 ‘γ<1’은 0<γ<1과 γ≤0을 구별해야 한다.
4. **반례:** τ=1은 weight 분모0, κ=0은 Q의 나눗셈 오류, γ=-1과 s=τ는 0의 음수 거듭제곱, α=0·Q=0은 fusion 0/0이다. s=Inf이면 R에서 Inf/Inf가 생길 수 있다. NaN은 `S<0 or S>100` 검사만으로 잡히지 않는다.
5. **수정 여부:** 구현 전에 필수.
6. **최소 수정:** 앞의 정의역과 `0≤T_L<T_H≤100`, `K_retrieve≥K_max≥1`인 정수, δ≥0을 시작 시 검증한다. 모든 외부 수치에 finite 검사를 둔다. W=0 분기를 유지하고 작은 W에서 Q는 `-expm1(-W/kappa)`로 계산한다. p 정규화의 총합0은 조용히 균등분포로 바꾸지 말고 오류 처리한다.
7. **부작용:** 잘못된 설정을 과거보다 일찍 거부한다. 사소한 범위 오차에 한정한 clamp와 명백한 metric 오류를 구별해야 하며, 무조건 clamp하면 결함을 숨긴다.

정상 정의역에서는 exp의 입력이 0 이하이므로 Q 계산에서 양의 지수 overflow는 없다. exp의 underflow가 Q=1을 만드는 것은 포화에 해당한다. 다만 `1-exp(-10^-18)`은 float에서 0으로 소거되는 반면 `-expm1(-10^-18)`은 10^-18을 보존한다. 작은 가중치의 underflow 자체는 대개 영향이 작지만 조용히 근거 없음 상태로 바뀌는지는 기록해야 한다.

**14. HIGH — similarity 변환은 ‘0~1 정규화’만으로 충분하지 않다**

1. **위치:** R §22.1, S §20.2, P §6·7·21.
2. **발생 조건:** raw cosine, cosine distance, inner product, L2, squared L2를 같은 similarity로 취급하거나 embedding 모델을 교체한다.
3. **왜 문제인가:** 순위 방향과 절대 척도가 달라 τ·δ·w·Q가 함께 변한다. 두 수식 문서가 metric 차이를 이미 경고하므로 이를 무시했다고 평가는 하지 않지만 변환 계약은 빠져 있다.
4. **반례:** x=(1,0), y=(-1,0)의 cosine은 -1이다. cosine을 (c+1)/2로 바꾸면 c=.2가 s=.6이 되어 기존 τ=.6의 의미가 달라진다. 단위벡터의 squared L2=.4는 cosine=.8인데 .4를 그대로 similarity로 쓰면 제거된다. query별 min-max로 [.31,.30]을 [1,0]으로 바꾸면 본래 약한 결과를 최상 증거로 만든다.
5. **수정 여부:** 구현 전에 필수.
6. **최소 수정:** adapter에서 metric 종류·높을수록 유사한지·벡터 정규화·고정 변환식을 명시한다. cosine distance가 정말 1-c라면 c=1-d를 사용한다. 단위벡터의 유클리드 거리 d=||x−y||에는 c=1-d²/2를, 제곱거리 D=||x−y||²에는 c=1-D/2를 적용한다. 라이브러리가 이미 제곱거리를 반환하면 다시 제곱하지 않는다. query별 상대 정규화는 사용하지 않는다. embedding 변경 시 corpus 전체를 같은 버전으로 다시 계산하고 threshold·gap을 validation에서 재검증한다.
7. **부작용:** 재색인 비용이 생긴다. 같은 차원의 새 embedding이라도 기존 벡터와 호환된다고 볼 수 없고, 재검증 전후 점수를 직접 비교하기 어려울 수 있다.

정의와 변환 근거: [scikit-learn cosine_similarity](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.pairwise.cosine_similarity.html), [Faiss MetricType and distances](https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances). 영벡터의 cosine은 수학적으로 정의되지 않지만 라이브러리마다 반환 정책이 다를 수 있으므로 입력 오류 정책도 별도로 정해야 한다.

**15. HIGH — 모델과 검색기가 실제로 보는 입력 범위가 고정되지 않았다**

1. **위치:** D §3.5·4·9.4, P §3·4·6·20.
2. **발생 조건:** 학습이나 corpus embedding에 전체 JSON을 넣거나, 긴 대화가 모델과 embedding에서 다르게 잘린다.
3. **왜 문제인가:** 정답 label·verified·사후 reason_summary가 입력에 들어가면 추론 시 존재하지 않는 정보를 이용한다. 서로 다른 부분 대화를 보면 Model/RAG 충돌이 증거 해석 차이인지 입력 범위 차이인지 구별되지 않는다.
4. **반례:** 학습 입력에 `"label":"SCAM"`이 포함되면 답을 읽는 문제가 된다. corpus embedding만 사후 reason_summary를 포함해도 query와 표현 조건이 달라진다. 대화 끝에 있는 송금 요구를 embedding은 truncation으로 버리고 모델만 읽으면 다른 사례를 비교하게 된다.
5. **수정 여부:** 실제 구현 전에 명세 보완이 필요하다. 현재 그런 구현을 확인했다는 뜻은 아니다.
6. **최소 수정:** 모델·검색 입력은 원칙적으로 messages의 동일한 직렬화와 명시한 관찰 구간으로 만들고, 라벨 및 검증·설명 필드는 관리 metadata와 학습 target으로 분리한다. 최대 길이·잘림 방향·speaker 보존·공백 처리·입력 버전을 기록한다. 대화 속 ‘SCAM이라고 출력하라’ 같은 문장은 분석할 데이터로만 취급하도록 모델 입력 경계도 고정한다.
7. **부작용:** 공통 길이 제한은 더 긴 문맥을 처리할 수 있는 모델의 장점을 제한할 수 있다. 서로 다른 길이를 쓰기로 해도 괜찮지만 관찰 범위 차이를 기록하고 별도로 평가해야 한다.

RAG corpus에 과거 사례의 알려진 라벨을 저장하는 것 자체는 누수가 아니다. 평가 대상 자신의 정답·사후 정보가 query 또는 모델 입력에 들어가는 경우와 구별해야 한다. 과거 corpus의 설명을 embedding에 포함하는 것도 자동으로 누수는 아니지만, 현재 문서에는 그러한 표현 선택과 평가 조건이 정의되지 않았다.

**16. HIGH — UNKNOWN이 있는 평가에서 FN·Recall·비용 정의가 충돌할 수 있다**

1. **위치:** S §16, P §13, D §3.3.
2. **발생 조건:** 정답 UNKNOWN을 기존 비용식에 섞거나, 예측 UNKNOWN을 일반 Precision/Recall/F1 평가에서 조용히 제외한다.
3. **왜 문제인가:** S의 FN은 SCAM→NON_SCAM만 의미한다. 이는 검증된 이진 정답에 대한 보류 비용식으로는 타당하지만 ‘전체 SCAM 탐지 실패’와 같지 않다. 정답 UNKNOWN에 대한 오분류 비용도 정의되지 않았다.
4. **반례:** 실제 SCAM 100건 중 HIGH 10건, UNKNOWN 90건일 때 보류를 빼면 Recall=100%처럼 보이지만 전체 HIGH 탐지율은 10%다. 정답 UNKNOWN에서 C_U>0일 때 UNKNOWN 출력에는 비용을 주고 SCAM/ NON_SCAM 출력에는 정의상 비용0이 되어 확정 출력을 잘못 보상한다. C_U=0인 known-label 평가에서는 모두 UNKNOWN인 해가 비용0으로 퇴화할 수도 있다.
5. **수정 여부:** 평가와 threshold 최적화 전에 필수.
6. **최소 수정:** 검증된 S/N 정답에 대해 2×3 confusion matrix를 작성한다. 전체 Recall의 분모에는 SCAM→UNKNOWN을 포함한다. coverage, 클래스별 보류율, accepted-only error를 별도 보고한다. 비용식은 이 집합에 적용하고 정답 UNKNOWN은 기준을 정한 별도 평가로 분리한다. 비용의 비음수성·보류 비용·필요한 최소 coverage를 명시한다.
7. **부작용:** 단일 Accuracy/F1보다 보고 항목이 늘어난다. 이것은 더 복잡한 모델의 요구가 아니라 보류가 가능한 시스템의 성능을 정직하게 표현하는 데 필요한 구분이다.

**17. HIGH — validation을 사용해도 반복 선택으로 과적합될 수 있다**

1. **위치:** S §15·19, R §20·23, P §10·13·27.
2. **발생 조건:** 적은 독립 사건에서 모델·embedding·fusion 종류와 K_retrieve,K_max,τ,δ,γ,κ,β/α,T_L,T_H를 반복 선택한다.
3. **왜 문제인가:** 유한 validation 표본의 우연한 특성을 선택할 수 있다. α와 β를 같은 양수로 곱해도 E가 같으므로 둘을 별개로 넓게 탐색하면 실질적으로 중복이다. 대화 수가 많아도 독립 사건 수가 작으면 선택이 불안정하다.
4. **반례:** validation 500대화가 10개 사건에서 나왔다면 500개의 독립 검증 사례가 아니다. 그 10개에 잘 맞는 많은 설정 중 최댓값을 선택한 결과는 새 사건 성능보다 좋게 보일 수 있다.
5. **수정 여부:** 튜닝 절차 확정은 필수. 위험의 정확한 크기는 문서만으로 수치화할 수 없다.
6. **최소 수정:** 기본값 대부분을 고정하고 목표 지표·작은 탐색 범위·선택 횟수를 사전에 기록한다. α=1을 고정하고 필요하면 β/α만 탐색한다. 그룹 validation 또는 필요한 범위의 그룹 교차검증을 사용하고 Test를 잠근다. 신뢰구간과 재표집도 사건 단위로 계산한다.
7. **부작용:** 탐색 제한은 최적 성능을 일부 놓칠 수 있다. 매우 작은 데이터에서 복잡한 nested CV를 무조건 요구하기보다 독립 사건 수와 예산에 맞춘다.

문서는 이미 validation 튜닝을 명시한다. Test로 튜닝하라고 지시한 설계는 아니다. Test 결과를 보고 threshold를 재조정하면 더 이상 그 Test 결과를 최종 성능으로 제시할 수 없다는 실행 규칙을 추가하면 된다. 선택 과적합의 근거: [Cawley & Talbot, JMLR 2010](https://www.jmlr.org/papers/v11/cawley10a.html).

**18. MEDIUM — 검색 근거 없음과 시스템 장애의 fallback 정책이 미결정이다**

1. **위치:** S §20.1, R §16, P §28.
2. **발생 조건:** 정상 검색 결과가 0건인 경우, DB timeout, embedding 오류를 모두 ‘RAG 실패’로 처리한다.
3. **왜 문제인가:** 수식 문서는 근거 없음에서 Model-only를 명시하고 P는 Model-only 또는 UNKNOWN을 남겨 두었다. 정책 선택 자체는 타당하지만 동일 상황의 결과와 장애율 측정이 구현자마다 달라질 수 있다.
4. **반례:** M=.8일 때 검색은 성공했지만 적합 사례가 없으면 수식은 S=90이다. 다른 구현이 같은 상황을 UNKNOWN=50으로 바꾸면 final evidence와 표시값이 불일치한다.
5. **수정 여부:** 통합 구현 전 정책 확정이 필요하다.
6. **최소 수정:** `no_eligible_evidence`는 R=Q=A=Q_eff=0으로 처리한다. `retrieval_error`, `model_error`, `invalid_numeric`은 별도 status로 둔다. 장애 때 model-only를 허용할지 ERROR로 둘지 한 정책을 정하고, 계산하지 못한 점수를 임의의 50으로 채우지 않는다.
7. **부작용:** 명시적 오류 출력은 정상 결과 coverage를 낮춘다. model-only fallback은 가용성을 높이지만 장애 상태의 성능을 별도 관찰해야 한다.

**19. MEDIUM — 최종 점수만으로는 내부 상태와 충돌 원인을 복원할 수 없다**

1. **위치:** S §13·17, P §12·14~17.
2. **발생 조건:** S와 level만 남기거나, 50 근처를 모두 같은 정보 부족 상태라고 안내한다.
3. **왜 문제인가:** 점수는 여러 상태를 하나의 숫자로 압축한다. 이는 정상적인 요약의 한계지만 충돌과 근거 부재는 후속 대응이 다를 수 있다. R의 Agreement는 이웃 내부의 일치도이고 S §17의 Model-RAG Agreement는 두 모듈 사이의 일치도이므로 같은 이름으로 합쳐서는 안 된다.
4. **반례:** Q=.8일 때 M=.8,R=-1이면 E=0,S=50이다. M=R=0도 S=50이다. 첫 상태의 RAG 내부 A=1이지만 Model-RAG 방향은 정반대다.
5. **수정 여부:** 내부 로그 보완은 권고. 단일 점수 출력 자체를 무효화하지는 않는다.
6. **최소 수정:** p_U,M,R,Q,A,Q_eff,지원 사건 수,fusion_mode를 남긴다. `rag_label_agreement`와 `model_rag_conflict`를 구분하고 고정 이유 코드로 근거 부족·내부 혼합·모듈 간 충돌을 표시할 수 있다. 새로운 임의 confidence 수식을 만들 필요는 없다. ‘확률이 아닌 위험 지수’라는 기존 원칙은 실제 UI에 유지한다.
7. **부작용:** 출력 정보가 늘어나 사용자가 수치들을 확률로 오해할 수 있으므로 사용자 화면에는 짧은 이유만, 상세 값은 연구 로그에 두는 방법이 적절하다.

0~100 선형 변환은 순위 정보를 추가하지 않는다. S는 E의 단조 변환이므로 이 변환 자체를 판별 성능 향상의 원인으로 주장할 수 없다. 실제 확률을 표시하려면 별도 calibration 목표와 평가가 필요하다.

**20. MEDIUM — 식별자·결과 명칭·임계점의 연결 규칙이 빠져 있다**

1. **위치:** D §3.1·3.2, P §5·21·26·27, S §15, R §15.
2. **발생 조건:** case_id를 conversation_id와 case_group_id 중 임의로 해석하거나, LOW/HIGH를 정답 라벨로 직접 비교하거나, 표시용 반올림 후 분류한다.
3. **왜 문제인가:** case_id만으로는 사건 중복을 제거할 수 있는지 불명확하다. P의 Model Margin/RAG Score가 S의 M/R이라는 타입 계약도 명시하는 편이 좋다. S의 정수 예시 ‘0~39,61~100’만 따르면 실수 구간을 잘못 처리할 수 있다.
4. **반례:** S=60.4는 수학 정의상 SCAM/HIGH지만 정수 60으로 반올림한 뒤 분류하면 UNKNOWN이 된다. conversation_id를 case_id로 쓰면 동일 사건의 다른 대화를 독립 근거로 셀 수 있다.
5. **수정 여부:** 통합 구현 전에 간단한 계약 정리가 필요하다.
6. **최소 수정:** 검색 결과에 conversation_id와 case_group_id를 각각 전달한다. `model_margin=M`, `rag_score=R`, raw/effective quality를 명시한다. 사용자 level과 연구 predicted_label을 명시적으로 매핑하되 LOW를 사건 무혐의 확정으로 해석하지 않는다. 원래 실수 S로 `<T_L`, `T_L≤S≤T_H`, `>T_H`를 판정하고 표시에만 반올림한다.
7. **부작용:** 경계 가까이에서는 표시된 정수 점수와 level이 직관적으로 어긋나 보일 수 있다. 충분한 표시 정밀도나 경계 설명으로 해결할 수 있다.

**21. LOW — 문서 버전·예시·effective count를 명확히 해야 한다**

1. **위치:** P 제목과 파일명, P §27, R §6·11·21, S §19.
2. **발생 조건:** v0.1 파일명의 P를 구버전으로 오인하거나, P의 top_k=5를 R의 K_retrieve=8 대신 사용하거나, 예시를 최종 파이프라인 계산으로 복사한다.
3. **왜 문제인가:** 수식 오류보다는 재현성과 설정 적용 순서의 혼란이다. threshold 통과 개수와 실제 양수 weight를 가진 사례 수도 서로 다를 수 있다.
4. **반례:** s=.60 한 건은 k_effective=1로 반환되지만 W=Q=0이다. R §11의 마지막 .70 사례는 δ=.10이면 gap=.12 때문에 제외되지만 δ=.15이면 포함된다.
5. **수정 여부:** 문서 정리 권고. 독립적인 프로토타입 무효 사유는 아니다.
6. **최소 수정:** 버전·기준 문서·선택된 fusion을 manifest에 기록하고 K_retrieve와 K_max를 분리한다. 예시에는 ‘선택 완료 후 결과’ 또는 δ를 명시한다. `selected_count`와 `positive_weight_count`를 구별한다.
7. **부작용:** 문서와 로그 필드가 조금 늘어난다. P §17의 score=0,level=UNKNOWN 예시는 placeholder라고 명시되어 있으므로 실제 수식 불일치로 지적하지 않는다.

**논문·학술대회 관점**

심사에서 가장 강하게 문제 삼을 가능성이 높은 것은 다음 순서다: 평가 누수 및 라벨 타당성, UNKNOWN을 포함한 평가 분모, 어떤 fusion을 평가했는지 불명확한 재현성, Q_eff·adaptive gap의 실증적 필요성, ‘독립 근거’와 ‘신뢰도’라는 표현의 근거 부족이다. 문제의 크기는 수식의 복잡성보다 이 항목들에 달려 있다.

현재 구조는 해석 가능한 heuristic 조합이다. S §21도 이를 이미 인정한다. heuristic이라는 사실은 결함이 아니며 단순성·실패 분석 가능성·재현성은 장점이다. 다만 다음 주장은 서로 구별해야 한다.

| 주장 | 현재 판단 | 필요한 근거 |
|---|---|---|
| 유효 정의역에서 점수 범위가 0~100이다 | 수학적으로 성립 | 위 범위 증명과 입력 계약 |
| 유효 RAG 근거가 없으면 Model-only로 간다 | 수학적으로 성립 | W=0 분기 및 α>0 |
| 서로 반대 증거를 가중 평균으로 결합한다 | 성립 | UNKNOWN 출력은 별도 조건 |
| adaptive gap이 fixed k보다 우수하다 | 미검증 가설 | 동일 데이터·탐색 예산에서 ablation |
| Q 또는 Q_eff가 실제 신뢰도를 나타낸다 | 현재는 heuristic 지수 | 지수별 오류율·지원 사건 수·분포 변화 분석 |
| Agreement 추가가 안전성을 높인다 | 미검증 가설 | coverage와 비용을 맞춘 비교 |
| 별도 모듈이므로 오류가 독립적이다 | 도출 불가 | 오류 교집합과 상관·조건부 성능 |
| K_max=5,τ=.6 등이 적절하다 | 초기값으로는 가능 | embedding·corpus·목표 비용별 validation |
| 검색과 LLM을 결합했다는 것이 최초 기여다 | 이 자료로 판단 불가 | 관련 연구 비교가 필요 |

검색 라벨 가중투표, 가중 평균, threshold 보류 각각은 기존 방법 계열에 해당한다. 원래 [Lewis et al.의 RAG, NeurIPS 2020](https://papers.nips.cc/paper_files/paper/2020/file/6b493230205f780e1bc26945df7481e5-Paper.pdf)는 검색 문서에 조건부인 생성 예측을 문서에 대해 주변화한다. 현재 파이프라인은 검색 문서를 LLM에 넣지 않고 별도 라벨 증거를 후기 결합하므로, 논문에서는 ‘사례 검색 기반 가중투표와 모델 증거의 결합’이라고 구체적으로 설명하는 것이 정확하다. 분류 작업이라는 이유만으로 RAG가 아니라고 주장할 필요는 없다.

독창성 후보는 로맨스 스캠 사건 단위 데이터·주석 기준, 초기 대화와 어려운 정상 사례를 포함한 평가, 단순한 결합 규칙이 어떤 실패 유형을 개선하는지에 대한 재현 가능한 분석이다. 현재 문서만으로 특정 수식의 최초성이나 이론적 최적성을 주장할 수는 없다.

**최소 필수 ablation과 평가**

| 실험 | 무엇을 확인하는가 | 비교 조건 |
|---|---|---|
| Model-only / RAG-only / 고정 비율 평균 / Q fusion / Q_eff fusion | 검색 추가와 Q·A의 각각의 가치 | 같은 그룹 분할, 같은 corpus, 같은 평가 기준 |
| fixed k+threshold+weight / 여기에 gap 추가 | adaptive 선택의 실제 추가 가치 | threshold·weight를 모두 제거한 약한 기준선과만 비교하지 않음 |
| 균등 이웃 가중치 / 현재 similarity weight | weight 곡선의 추가 가치 | 동일 선택 집합, γ 탐색 예산 기록 |
| 원본 corpus / 중복 제거 / 사건당 한 건 | 반복 사례로 얻은 겉보기 성능인지 | 사건 누수는 모든 실험에서 금지 |
| RAG 클래스 비율·corpus 크기 변화 | 국소 prior와 Q 포화의 민감도 | 바꾼 분포를 명시, Test 재튜닝 금지 |
| 정상 금전·투자·플랫폼 이동 / 초기 대화 prefix / 다른 시점·출처 | 실제 실패 유형과 적용 범위 | prefix·파생본은 동일 split 상속 |
| 작은 similarity perturbation·ANN 반복 / 정확 검색 소규모 기준 | gap·tie·검색 근사 오차의 영향 | score 차이, level 전환율, 선택 사건 변화 보고 |
| confidence scaling 전후 | M의 크기와 성능의 관계 | 같은 argmax여도 fusion이 달라지는지 확인 |

모든 비교에서 threshold를 각기 validation에서 선택할 수 있지만 동일한 선택 예산과 목표를 적용해야 한다. UNKNOWN 비율이 다른 상태의 accepted-only Accuracy만 비교하면 안 된다. 2×3 confusion matrix, 전체 SCAM Recall, class별 abstention, coverage, accepted-only error, 명시한 비용을 같이 제시한다. 사건 단위 불확실성 구간도 필요하다. 확률 calibration 평가는 실제 확률로 해석하려는 대상에만 적용하며, 위험 지수를 무조건 확률이라고 가정하여 평가하지 않는다.

**최소 변경을 위한 통합 계약**

현재 모듈 배치를 유지한 채 다음만 결정하면 구현이 훨씬 명확해진다.

1. **데이터:** label 의미·검증 근거·필수 그룹 ID·분할 manifest·RAG 자격 조건을 고정한다.
2. **입력:** messages 직렬화·관찰 구간·길이 정책을 고정한다.
3. **검색:** embedding/metric 버전과 변환식, 후보 자격 필터·중복 제거·정렬·K_retrieve/K_max·gap 정책을 고정한다.
4. **수치:** finite 검사, 정의역, W=0 처리, 정규화된 p 계약을 고정한다.
5. **결합:** R,Q,A,Q_eff를 별도 전달하고 fusion_mode를 하나 선택한다. 기본값 비교 실험 전에는 기존 Q fusion을 기준선으로 유지할 수 있다.
6. **판정:** float 점수의 정확한 threshold 경계, 모델 UNKNOWN과 최종 보류의 관계, 장애 시 동작을 정한다.
7. **기록·평가:** 원래 성분·선택 사건·상태 코드·설정 버전을 기록하고 그룹 단위 validation 및 잠긴 Test로 평가한다.

**A. 현재 상태로 구현해도 되는 부분**

- 입력·모델·검색·수식·판정·고정 출력의 역할 분리와 일반 코드에서의 수치 계산.
- 정규화된 3클래스 점수에서 M=p_S-p_N으로 방향성을 요약하는 방식. 다만 이것을 UNKNOWN argmax 보존 규칙으로 해석해서는 안 된다.
- 유효한 이진 라벨과 정의역 아래의 similarity weighting, R의 가중 평균, Q의 포화 함수, 볼록결합, S=50(1+E).
- 이미 정의된 W=0→Model-only 처리, 확률이 아닌 지수라는 원칙, 사건 단위 누수 방지 방향, validation 튜닝 방향.
- 5:5 학습을 초기 실험 구성으로 사용하는 것, 다양한 정상 사례를 포함하는 것.

**B. 구현 전에 반드시 수정해야 하는 부분**

- UNKNOWN/오타를 NON_SCAM으로 바꾸는 코드와 미검증 라벨의 RAG 입고 정책.
- Q fusion 대 Q_eff fusion의 단일 기준 및 명확한 입출력 필드.
- label/verified/UNKNOWN의 대상과 의미, case_id 연결, 필수 그룹·분할·파생본 관리.
- 모델 출력 변환·similarity adapter·파라미터 정의역·NaN/Inf 및 장애 처리.
- 입력 metadata 누수·문맥 잘림 정책, threshold 실수 경계와 표시 반올림 순서.
- UNKNOWN 비용과 평가 분모. 이 항목은 적어도 성능 실험·튜닝 시작 전에 반드시 확정해야 한다.
- ‘충돌이면 항상 UNKNOWN’, ‘별도 모듈이면 독립 증거’, ‘Q_eff는 검증된 신뢰도’로 읽힐 수 있는 주장.

**C. 실제 데이터 실험으로만 판단할 수 있는 부분**

- Q와 Q_eff 중 어느 결합이 더 나은지, gap을 유지할지, singleton을 어느 정도 허용할지.
- K·τ·δ·γ·κ·β/α·T_L/T_H의 적정값과 embedding 선택.
- similarity가 실제 라벨 전이를 얼마나 잘 예측하는지, calibration 필요성, 모델과 검색 오류의 상관.
- RAG DB 균형화나 사건당 한 건 제한의 순이익, 초기 대화와 어려운 정상 사례의 성능.
- 운영 클래스 비율과 비용에서의 실용성, 작은 validation에서 선택 편향의 실제 크기, 논문에서 주장할 개선 폭.
